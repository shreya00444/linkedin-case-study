LinkedIn Talent Solutions — Q3 2025 Forecast & Planning Tool

A lightweight prototype that automates forecast accuracy analysis and Q3 pipeline planning by unifying CRM pipeline, historical bookings, and rep forecast submissions into a single repeatable pipeline.

---

The Problem

Q3 planning was slow and unreliable because data lived in three separate places, every region used different forecast logic, and by the time leadership saw the numbers the data was already stale. This tool fixes all three.

---

Assumptions

Planning context: Dataset is structured as of Q2 2025. I used 2025-Q1 close dates as the planning window proxy since Q3 2025 opportunities have not been entered yet. In production the tool dynamically detects the current planning quarter.

Forecast accuracy quarters: Only 2024-Q3 and 2024-Q4 are used for accuracy analysis — the only quarters where both rep submissions and actual bookings exist for comparison.

Q3 target baseline: Average of 2023-Q3 and 2024-Q3 actual bookings. Planning for Q3 so we benchmark against what Q3 has historically delivered.

Test data: REP-099 and ACC-999 are excluded based on their IDs falling outside the normal range. In production this uses an official CRM exclusion list from data engineering.

Coverage threshold: Strong/At Risk/Critical labels use 3x as the healthy threshold — a standard B2B benchmark, not LinkedIn-specific. Should be calibrated to LinkedIn win rates by segment in production.

Region and segment enrichment: Rep forecast submissions do not include region or segment. I joined to opportunities on account_id to get these dimensions. In production they should be included directly in the submission table.

Deduplication: OPP-1004 is both a duplicate and stale. Deduplication runs first so it is counted once under Duplicate only.

AI Insights: Hardcoded for this demo. In production dynamically generated by the LLM API from live analysis results.

---

Metric Definitions

Weighted Forecast: pipeline_amount x likelihood_pct / 100. Adjusts deal value by rep confidence so a $500k deal at 20% contributes $100k not $500k.

Forecast Accuracy %: (1 - |Weighted Forecast - Actual Bookings| / Actual Bookings) x 100. Positive = under forecast. Negative = over forecast. 100% = perfect.

Accuracy Trend: Average accuracy per region or segment across quarters. Shows directional improvement or decline not just a snapshot.

Pipeline Coverage Ratio: Active Pipeline / Historical Q3 Target. Industry minimum is 3x — you need $3 in pipeline for every $1 of target to account for deals that slip.

Coverage Status: Strong = 3x or above. At Risk = 1x to 3x. Critical = below 1x. Based on B2B benchmarks not LinkedIn-specific data.

Pipeline Gap: Historical Q3 Target minus Active Pipeline. How much additional pipeline is needed to reach target.

Stale Deal: Open opportunity with a past close date not marked Closed Won or Closed Lost. Inflates pipeline with ghost inventory and excluded from Q3 analysis.

Rep vs CRM Gap: Rep pipeline_amount minus CRM pipeline_amount. Rep Higher means rep values deal above CRM. Rep Lower means below. Aligned means they agree.

Production Architecture

Every Monday at 7am a scheduled trigger would pull latest pipeline from the Dynamics 365 CRM API (LinkedIn's CRM system as specified in the case), pull latest bookings from the SQL bookings table, ingest latest rep forecast submissions, run data quality checks and alert the data team via Slack if anything fails, run all three analyses, refresh the dashboard, and email leadership a summary by 9am. No manual work. No Excel. Same logic every week.

Key changes from prototype to production: Excel replaced by live Dynamics API and SQL connections, static planning quarter replaced by dynamic date detection, hardcoded insights replaced by LLM API generating dynamic findings, pattern-based test exclusion replaced by official CRM exclusion list, manual run replaced by Airflow DAG or equivalent scheduler.

---
Data Quality Monitoring

Every run audits all three sources before analysis. Issues are logged with record ID, description, and action taken.

Ingestion checks:
- Duplicate opp_ids detected and removed
- Missing close dates flagged and excluded from Q3 pipeline
- Missing rep IDs flagged and excluded from rep analysis
- Missing pipeline amounts excluded from weighted forecast
- Zero likelihood submissions flagged and excluded
- Stale deals identified and excluded from active pipeline
- Test data records excluded via exclusion list
- Negative bookings flagged for review

Analysis checks:
- Row counts match expected after every merge
- All 4 regions present in output
- All 3 segments present in output
- Bookings totals reconcile exactly to source
- All forecast records matched to a CRM opportunity

In production any critical check failure surfaces a dashboard warning and fires a Slack alert to data engineering with the full issue log before the report reaches leadership.
